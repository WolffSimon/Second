# Excavation interview

**The axiom:** absence from the file is not absence from the career. The inventory records what has been asked, not what the person has done. Before any gap is written into a document or conceded in a letter, ask.

## When to run it

- A requirement in a posting has no receipt in the inventory.
- A reviewer, human or model, names a weakness.
- A build enters a new domain (a new sector, a new function, a new altitude).
- A profile claim needs the fact underneath it to be defensible across a table.

## How to write the questions

Aim each question at a nameable thing: a client, an artefact, a number, a system, a role held, a decision made. Ask for the instance and for the pattern: "did you ever…" and "how often, and with what." Group questions by the requirement they serve so the person can answer in any order. Number them so a voice note can say "seven, yes." Give a plausible answer shape when it helps ("a virtual group, twelve people, no budget"), because it shows the size of answer that would suffice. Keep each question to two sentences. Ten to fifteen questions is a set; more is a burden.

Ask the awkward questions plainly. The person will say "don't bother" to the ones that don't matter, and that answer closes the line cleanly.

## What to do with the answers

Bank every answer the same day in the inventory, dated, in the person's words, with any usage ruling they attached ("true, never used", "conversation only", "confirm before it appears anywhere"). Convert a "yes" into a sentence on the document that prompted the question. Convert a "no" into silence in the document and a closed line in the inventory, so the question is never asked twice. Never round an answer up: "I think I'm a member" is not a line on a CV; "very little of it was device farms" is an assessment to be labelled as the person's view, not a statistic.

## The instance and the pattern

When the person says "I did that every day for years," the document states the pattern and never the single remembered instance. When the person says "I did it once," the document usually stays silent unless the once was large.

## Confidentiality

Some answers are true and unusable: a former employer's internal detail, a client's confidential circumstances, a vendor's name. Bank the fact with the restriction and write the generic form on any document ("the incumbent provider", "an ad server", "a US bank").
